### 2.2 Carteira — CARTA-001 (28/08/2026), hierarquicamente superior

Fonte: `docs/decisions/CARTA-001-CARTA-DA-CARTEIRA.md` no repositório público.

`DECISÃO` Quatro invariantes permanentes:

- **I-1 Código aberto.** Código público, GPL-3.0-or-later, verificável. Ninguém precisa confiar no proprietário, no projeto ou em qualquer agente: precisa poder ler.
- **I-2 Autocustódia total.** O usuário controla geração, uso, guarda e recuperação. Seed, chave privada e material de assinatura nunca saem do aparelho por canal nenhum. Nenhum servidor, mantenedor, provedor, conector ou agente recebe custódia, poder de assinatura ou poder de recuperação. Se o projeto acabar amanhã, quem tem a frase de recuperação continua dono.
- **I-3 Sem servidor do projeto; o usuário alimenta o próprio nó.** Caminho padrão = nó Bitcoin do usuário. Alternativa de terceiro só se for explícita, nunca silenciosa, com a tela dizendo o que aquele servidor passa a saber, e o nó próprio permanece de primeira classe.
- **I-4 Nada é declarado funcionando antes de auditoria independente.** Nenhuma pessoa — inclusive o proprietário — recebe da boca do projeto a informação de que esta carteira é segura, pronta ou confiável, antes de auditoria externa independente com evidência publicada.

`DECISÃO` Gate único (G-ÚNICO): a auditoria.

- Antes: engenharia é livre (na faixa Signet/Demo).
- Depois: começa o lançamento.
- O gate incide sobre a **afirmação**, não sobre o trabalho de laboratório.

`DECISÃO` Do outro lado do gate, sem exceção:

- nenhum satoshi real, de ninguém, inclusive do proprietário;
- Mainnet não é tocada;
- nenhuma seed real de usuário entra no cofre;
- distribuir é permitido; vender confiança não é.

`DECISÃO` Na faixa simultânea Signet ou Demo + material descartável + valor econômico zero, o trabalho é livre: gerar/importar mnemonic de teste, derivar, consultar cadeia, montar PSBT, assinar, transmitir, ligar ao nó próprio, escrever e apagar telas. Sem ADR prévia, sem “autorização de agente”.

## 9. Protocolo para registrar novas decisões sem apagar o histórico

`DECISÃO` de processo, alinhada à CARTA-001 (“nenhum documento anterior é apagado; passa a ser lido através do documento superior”).

1. **Não apagar.** Proibido reescrever v1 no lugar para “ficar limpo”. Proibido silenciar rejeição (símbolo C, moeda/raio, Mainnet, etc.).
2. **Uma decisão por registro.** Data, autor (proprietário), etiqueta `DECISÃO` / `FATO` / `PENDENTE`, fonte, efeito sobre documentos anteriores.
3. **Onde gravar.**
   - Carteira / segurança / rede / cofre → `docs/decisions/` no repo, nome estável.
   - Marca / canal / Shorts / plataformas → emenda no próximo `SYNC-IA-DIVINO-BITCOIN-vN.md` +, se permanente de marca, atualização datada da identidade visual com versão nova.
   - Papel das IAs → emenda de `docs/ALINHAMENTO-IA.md` **e** do próximo SYNC.
4. **Reabertura de rejeitado.** Só com evidência nova + experimento com uma variável + aprovação explícita do proprietário. Sem isso, a resposta da IA é “já rejeitado em [data]”.
5. **Conflito.** CARTA-001 resolve carteira. Este SYNC resolve estado compartilhado entre IAs. Proprietário resolve o resto. Agente não vota.
6. **Correção factual.** Número de inscritos, views, URL: atualizar no próximo SYNC com data da medição. Não transforma medição antiga em erro moral; deixa o histórico datado.
7. **O que não vira decisão.** Ideia de chat, preferência estética solta, “fiquei melhor assim”, texto gerado sem aprovação. Isso é rascunho.

Modelo mínimo de emenda:

```
DATA:
FRENTE: canal | marca | app | repo | ia
TIPO: DECISÃO | FATO | PENDENTE | REVOGAÇÃO
ENUNCIADO:
FONTE:
O QUE NÃO MUDA:
EFEITO SOBRE DOCS ANTERIORES: (não apaga; passa a ser lido através desta emenda)
```
